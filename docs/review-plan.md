# План Code Review модуля расчета корзины (`src/discount.py`)

## 1. Цели ревью
- Проверка математической точности расчета скидок и финальной стоимости корзины.
- Защита от фрода (проверка корректности срабатывания ограничения максимальной скидки в 30%).
- Проверка логики последовательного применения промокодов и уровней лояльности.

## 2. Измеримые критерии приемки
- Отсутствие «магических чисел» (все пороги и коэффициенты вынесены в именованные константы).
- Наличие валидации входных данных (сумма корзины не отрицательная, типы аргументов корректны).
- Покрытие модульными тестами (Unit-tests) > 80%.
- Успешное прохождение линтера `flake8` без предупреждений.

## 3. Участники и роли
- **Автор кода:** Разработчик микросервиса (подготовка Pull Request, написание тестов, исправление замечаний).
- **Ревьюер (Code Owner):** Tech Lead (проверка бизнес-логики, безопасности и соответствия стандартам).

## 4. Механизм эскалации при спорах
- Если автор и ревьюер не приходят к согласию в комментариях к PR в течение 24 часов, спорный вопрос выносится на обсуждение команды или решается финальным голосом Tech Lead с обязательной фиксацией решения в ADR (Architecture Decision Record).
